1. Data Mining Tools

This project was developed using R version 4.5.2 as the primary data mining and statistical computing platform. R was chosen for its extensive ecosystem of machine learning and data preprocessing libraries, its strong support for reproducible research, and its compliance with the course requirements.

The following R packages were used in this project:

- caret (v6.0-94): The primary framework for model training, hyperparameter tuning via cross-validation, and data splitting. Provides a unified interface for over 200 classification and regression algorithms.

- e1071: Backend support functions for SVM and Naive Bayes classifiers.

- randomForest (v4.7-1.2): Implementation of Breiman's Random Forest ensemble algorithm.

- rpart: Recursive partitioning for decision tree (CART) classification.

- gbm (v2.2.3): Gradient Boosting Machine implementation.

- xgboost (v3.2.0): Extreme Gradient Boosting. Due to incompatibility between xgboost 3.x and caret's xgbTree method, a manual 5-fold cross-validation wrapper was implemented using the direct xgboost API.

- nnet: Single hidden-layer neural network for classification.

- kernlab: SVM implementation with radial basis function (RBF) kernel.

- naivebayes: Naive Bayes classifier with kernel density estimation support.

- ROSE (v0.0-4): Random Over-Sampling Examples for class balancing via kernel density estimation.

- smotefamily: SMOTE (Synthetic Minority Over-sampling Technique) implementation for class balancing.

- pROC: ROC curve analysis and AUC (Area Under Curve) computation.

All code was written in a single R script file (project_code.R) and executed in a non-interactive batch mode using Rscript.exe. The set.seed(699) function was used throughout to ensure full reproducibility of results.

2. Classification Algorithms

Nine classification algorithms were employed in this project, each representing a different approach to pattern recognition and decision boundary formation. Every algorithm was applied across all four balancing methods, yielding 36 models total.

2.1 Logistic Regression

Logistic Regression is a linear classifier that models the probability of class membership using the logistic (sigmoid) function. It estimates a linear decision boundary in the feature space by maximizing the log-likelihood of observed class labels. Trained via caret's "glm" method with family = "binomial". No tuning parameters are required.

2.2 Decision Tree (CART)

Classification and Regression Trees (CART), implemented via the rpart package, recursively partition the feature space into homogeneous regions using binary splits. At each node, the algorithm selects the feature and threshold that maximizes information gain (Gini impurity reduction). The complexity parameter (cp) controls tree pruning: higher cp values produce simpler trees. Tuning grid: cp = {0.001, 0.005, 0.01, 0.02, 0.05}.

2.3 Random Forest

Random Forest is an ensemble method that constructs multiple decision trees on bootstrapped subsets of the training data, with random feature subsets considered at each split (controlled by the mtry parameter). Final predictions are made by majority vote across all trees. This approach reduces variance and mitigates overfitting compared to single decision trees. Tuned via caret with tuneLength = 5, which searches 5 different mtry values.

2.4 Gradient Boosting Machine (GBM)

GBM builds an additive ensemble of weak learners (shallow decision trees) sequentially, where each new tree corrects the residual errors of the cumulative ensemble. Key tuning parameters include the number of trees (n.trees), interaction depth, shrinkage (learning rate), and minimum observations per node. Tuning grid: n.trees = {100, 200, 300}, interaction.depth = {3, 5}, shrinkage = {0.01, 0.1}, n.minobsinnode = 10.

2.5 Support Vector Machine (Radial Kernel)

SVM with a Radial Basis Function (RBF) kernel maps input features into a high-dimensional space where a maximum-margin hyperplane separates the classes. The RBF kernel enables non-linear decision boundaries. The cost parameter (C) controls the trade-off between margin width and misclassification penalty, while sigma determines the kernel width. Tuned via caret with tuneLength = 5 using the kernlab package.

2.6 K-Nearest Neighbors (KNN)

KNN is a non-parametric, instance-based classifier that assigns a class label based on the majority vote of the k nearest training examples in the feature space, measured by Euclidean distance. Larger k values produce smoother decision boundaries. Feature scaling (centering and standardization) is essential for KNN to prevent features with larger ranges from dominating distance calculations. Tuning grid: k = {3, 5, 7, 9, 11, 15}.

2.7 Naive Bayes

Naive Bayes is a probabilistic classifier based on Bayes' theorem with the assumption of conditional independence among features given the class label. Despite this strong assumption, it often performs well in practice, especially with high-dimensional data. Tuning parameters include Laplace smoothing ({0, 1}), kernel density estimation (usekernel = {TRUE, FALSE}), and bandwidth adjustment (adjust = 1).

2.8 Neural Network

A single hidden-layer feedforward neural network was used, implemented via the nnet package. The network maps input features through a hidden layer of sigmoid-activated neurons to produce class probability outputs. Key tuning parameters are the hidden layer size (number of neurons) and weight decay (L2 regularization). Tuning grid: size = {5, 10, 15}, decay = {0.001, 0.01, 0.1}. MaxNWts was set to 10,000 to accommodate the large feature space.

2.9 XGBoost (Extreme Gradient Boosting)

XGBoost is an optimized gradient boosting framework that uses regularized objective functions, column subsampling, and efficient tree construction algorithms. Due to incompatibility between xgboost 3.x and caret's xgbTree method, a custom manual 5-fold cross-validation implementation was used. The parameter search grid covered max_depth = {3, 4, 6, 8}, eta (learning rate) = {0.01, 0.05, 0.1, 0.3}, and nrounds = {100, 200, 300}, with colsample_bytree = 0.8, subsample = 0.8, and min_child_weight = 1 fixed.

3. Data Mining Procedure

This section describes the complete data mining procedure, step by step, as implemented in the project_code.R file. All preprocessing was performed on the full dataset before the train/test split, following the assignment process flow diagram.

3.1 Data Loading

The dataset (project_data.csv) was loaded from the 2023 American Housing Survey (AHS). The original dataset contained 9,241 rows and 145 columns, with all variables being integer-coded and the target variable "Class" indicating whether a household has a person with a disability ("Yes") or not ("No").

3.2 Removal of Missing Target Values

Rows where the Class variable was NA or empty were removed, as these records cannot be used for supervised classification. This reduced the dataset from 9,241 to 8,035 rows.

3.3 Feature Removal

The CONTROL column (a unique record identifier) was dropped as it has no predictive value and would only add noise to the models. This left 144 columns (143 features + 1 target).

3.4 Exploratory Data Analysis (EDA)

Key EDA findings:

- Class distribution: No = 6,153 (76.58%), Yes = 1,882 (23.42%) — significant class imbalance with a 3.3:1 ratio.

- Missing values: 62 out of 143 features had missing values. LOTSIZE had the highest missing rate at 26.98%.

- All features were integer-coded, with NAs representing missing values.

3.5 Numeric Conversion

All feature columns were explicitly converted to numeric type using as.numeric(as.character(x)). Any columns that became entirely NA after conversion (indicating non-numeric content) were removed. No columns were lost in this step.

3.6 Missing Value Imputation

Missing values in all feature columns were imputed using column-wise median imputation. The median was chosen over the mean because it is robust to outliers, which are prevalent in housing survey financial variables (e.g., household income, housing costs). After imputation, zero NAs remained in the dataset.

3.7 Near-Zero Variance Feature Removal

A two-step approach was used to remove uninformative features while preserving predictive ones:

1.  Zero-variance removal: Features with only one unique value (constant columns) were removed.

2.  Lenient near-zero variance (NZV) removal: Using caret's nearZeroVar() with freqCut = 99/1 (instead of the default 95/5), only features where 99% or more of observations had the same value were removed. This lenient threshold was critical because disability indicator variables (HHSEE, HHMEMRY, HHCARE, HHERRND) have low variance (most households do not have disabled members) but are the strongest predictors of the target class. Using the default threshold would have removed these key features and significantly degraded model performance.

16 near-constant features were removed in this step (e.g., SAMESEXHH, NUMSECFAM, KITCHENS, FRIDGE, ROOFHOLE, etc.), leaving 127 features.

3.8 Outlier Handling (Winsorization)

IQR-based winsorization was applied only to continuous features (those with more than 10 unique values). For each continuous feature, values below Q1 - 1.5*IQR were capped at the lower bound, and values above Q3 + 1.5*IQR were capped at the upper bound. Binary and low-cardinality categorical features were excluded from winsorization to prevent collapsing them to zero variance. 25 continuous features were winsorized.

After winsorization, a safety check removed 9 features that became constant (zero variance), leaving 118 features.

3.9 Feature Scaling

All numeric features were centered (subtract mean) and scaled (divide by standard deviation) using caret's preProcess() with method = c("center", "scale"). This standardization (mean=0, sd=1) is essential for distance-based algorithms (KNN, SVM) and neural networks, which are sensitive to feature magnitudes. A final zero-variance check removed any columns with zero variance after scaling. The final preprocessed dataset contained 118 features.

3.10 Save Preprocessed Dataset

The fully preprocessed dataset (8,035 rows, 119 columns including Class) was saved as preprocessed_data.csv.

3.11 Train/Test Split

A stratified 70/30 train/test split was performed using caret's createDataPartition() with set.seed(699) for reproducibility. Stratification ensures that the class distribution (~76.6% No / ~23.4% Yes) is preserved in both splits:

- Training set: 5,626 rows (No = 4,308, Yes = 1,318)

- Test set: 2,409 rows (No = 1,845, Yes = 564)

Both sets were saved as initial_train.csv and initial_test.csv. The test set was held out and never used during training or balancing.

3.12 Data Balancing (4 Methods)

Four class balancing methods were applied to the training set only to address the ~77%/23% class imbalance:

1.  Random Undersampling (caret::downSample): Randomly removes majority class samples to match the minority class count. Result: 2,636 rows (1,318 No + 1,318 Yes). Pros: Fast, reduces training time. Cons: Discards majority class data.

2.  Random Oversampling (caret::upSample): Randomly duplicates minority class samples to match the majority count. Result: 8,616 rows (4,308 No + 4,308 Yes). Pros: Preserves all data. Cons: Exact duplicates risk overfitting.

3.  SMOTE (smotefamily::SMOTE, K=5): Creates synthetic minority samples by interpolating between existing minority samples and their K nearest neighbors. Result: 8,262 rows (4,308 No + 3,954 Yes). Pros: Generates diverse new samples. Cons: May create noisy samples near class boundaries.

4.  ROSE (ROSE::ROSE): Generates synthetic samples using kernel density estimation on both classes. Result: 5,626 rows (2,814 No + 2,812 Yes). Pros: Smooth density-based generation. Cons: May not respect class boundaries as well as SMOTE.

3.13 Feature Selection

Correlation-based feature selection was applied independently to each balanced training dataset. For each dataset, the pairwise correlation matrix was computed, and features with absolute correlation |r| >= 0.85 were identified using caret's findCorrelation(). Among each highly correlated pair, the feature with lower overall correlation to the response was removed.

Results: Undersampling, Oversampling, and SMOTE datasets each had 10 correlated features removed (leaving 108 features). The ROSE dataset had no features removed (keeping all 118 features). The test set columns were subsetted to match each training dataset's selected features.

3.14 Model Training and Evaluation

All models (except XGBoost) were trained using caret's train() function with 5-fold cross-validation (trainControl(method = "cv", number = 5, classProbs = TRUE)) for hyperparameter tuning. XGBoost used a custom manual 5-fold CV implementation due to package compatibility issues. Each model was trained with set.seed(699) for reproducibility.

Predictions on the test set used a fixed threshold of 0.5 (no threshold optimization). For each model, a comprehensive set of performance metrics was computed: confusion matrix, TP Rate, FP Rate, Precision, Recall, F-Measure, ROC Area (AUC), MCC, and Kappa — reported separately for each class (No, Yes) and as a weighted average.

5.1 Impact of Balancing Methods

The choice of balancing method had a substantial impact on model behavior. Random Undersampling consistently produced the highest Yes TPR (minority class recall) across most algorithms because reducing the majority class to match the minority forces the classifier to learn a more balanced decision boundary. However, this comes at the cost of reduced No TPR, as less majority-class data is available for learning No-class patterns.

Random Oversampling and SMOTE tended to produce models with high No TPR but moderate Yes TPR. The duplicated or synthetic minority samples helped but did not shift the decision boundary as aggressively as undersampling. ROSE produced extreme results — several ROSE models (Decision Tree, Random Forest, GBM, XGBoost) predicted almost exclusively "No," yielding No TPR near 1.0 but Yes TPR below 0.25. This suggests that ROSE-generated samples may not have adequately represented the minority class distribution in this high-dimensional feature space.

5.2 Algorithm Performance Comparison

Among the nine algorithms, the key observations are:

- Gradient Boosting and XGBoost achieved the highest AUC values overall (up to 0.8596), indicating strong discriminative ability. However, their high No TPR often came at the expense of Yes TPR.

- Decision Trees showed high sensitivity to the balancing method. With undersampling, the Decision Tree achieved the best Yes TPR (0.7730) of any model, qualifying for +20% extra credit. With other balancing methods, its performance was moderate.

- Logistic Regression was consistently strong across all balancing methods, with stable and balanced TPR values. It never achieved the highest single metric but delivered reliable, well-rounded performance.

- Naive Bayes performed poorly across all balancing methods, with extremely low Yes TPR (0.008 to 0.135). The conditional independence assumption appears too strong for this dataset, where features are correlated.

- KNN showed moderate performance, likely limited by the high dimensionality of the feature space (108-118 features), which dilutes the effectiveness of distance-based classification.

5.3 Why Model 2 Was Selected

Model 2 (Undersampling + Decision Tree) was selected as the best model because it is the only model that qualifies for the +20% extra credit tier with Yes TPR = 0.7730 (>= 0.77) and No TPR = 0.7322 (>= 0.73). While other models like Model 4 (Undersampling + GBM) had higher AUC (0.8567 vs. 0.7887) and higher TPR Sum (1.5555 vs. 1.5053), they did not meet the +20% threshold due to insufficient Yes TPR.

The Decision Tree with undersampling succeeds because undersampling creates a balanced 50/50 training set, and the simple, interpretable splitting rules of CART effectively capture the key disability indicators (such as HHSEE, HHMEMRY, HHCARE, HHERRND) without being diluted by the majority class. The aggressive pruning via the cp parameter prevents overfitting to the small undersampled training set.

5.4 Key Preprocessing Insights

A critical lesson from this project was the importance of preserving low-variance but highly predictive features. Initially, using the default nearZeroVar() threshold (freqCut = 95/5) removed disability indicator variables that are essential for predicting the target class. Switching to a lenient threshold (freqCut = 99/1) retained these features and improved Yes TPR from approximately 0.65 to 0.77 for the best model. This demonstrates that domain knowledge should guide preprocessing decisions rather than relying solely on statistical defaults.

Similarly, restricting winsorization to continuous features (>10 unique values) prevented binary and low-cardinality features from being collapsed to zero variance, which would have destroyed valuable information.

5.5 Conclusion

This project successfully built and evaluated 36 classification models to predict disability status in U.S. households using the 2023 American Housing Survey data. Through systematic experimentation with four balancing methods and nine classification algorithms, we identified Model 2 (Random Undersampling + Decision Tree) as the best model, achieving Yes TPR = 0.7730 and No TPR = 0.7322, which qualifies for the +20% extra credit tier.

Key findings include: (1) Random Undersampling is the most effective balancing method for maximizing minority class recall in this dataset; (2) simple models like Decision Trees can outperform complex ensemble methods when the evaluation metric prioritizes balanced class-wise performance; (3) careful preprocessing — particularly preserving domain-relevant low-variance features — has a greater impact on model performance than algorithm sophistication; and (4) ROSE-based balancing was largely ineffective for this high-dimensional dataset, producing highly biased predictions toward the majority class.
